# 重做与运行记录协议

## 重做与备份

### 触发

- 阶段级：「重做分镜」= 重做阶段 1；「重做资产」= 阶段 2；「重做视频提示词」= 阶段 3。
- 细粒度：「修改第 N 镜」「重写人物 X 的设定」「第 N 到 M 镜重做」。

### 执行顺序（不可颠倒）

1. 读当前产物与 `历史版本/` 目录，确定版本号 vN（当前文件存在则 N = 已有备份数 + 1）。
2. 把当前文件复制为 `拆解结果/<剧本名>/历史版本/<文件名>.<vN>.<YYYYMMDD-HHMMSS>.md`。
3. 重生成当前文件（细粒度重做只改目标内容，其余保持）。
4. 备份保留：历史版本全部保留、不自动删除（本产品无 shell、无删除操作，安全围栏要求零破坏性行为）。同一文件备份数超过 3 版时，在汇报中说明「历史版本已累积 N 版，可自行在文件管理器中清理」，由用户决定。
5. 追加 run-log 行（动作 = 重做）。
6. 按汇报模板汇报。

### 下游一致性

- 阶段级重做后，下游产物可能不再与上游对齐（例如重做分镜后 02/03 可能过期）。汇报时明确提醒用户下游文件是否仍有效，是否也需要重做；由用户决定，不自动级联重做。
- 细粒度重做（单镜 / 单资产）后，提示对应下游引用点是否受影响。

### 幂等

- 同一剧本同一阶段已有产物时，不静默重跑。先读现有文件，向用户说明已有产物与落盘时间，用 ask_user_question 询问：重做（会先备份）/ 保留并继续 / 取消。用户未确认前不写任何文件。

## 运行记录（run-log）

### 位置与格式

- 文件：`.script-breakdown/run-log.md`（工作区根）。
- 首次写入时建立表头，之后只追加行：

```markdown
| 时间戳 | runId | 剧本名 | 动作 | 产物路径 | 备份路径 |
|---|---|---|---|---|---|
| 2026-08-17T03:13:18Z | 深夜面馆-20260817 | 深夜面馆 | 阶段1 | 拆解结果/深夜面馆/01-分镜总表.md | — |
```

- runId = `<剧本名>-<YYYYMMDD>`；同剧本同日另起新运行用 `-2`、`-3` 后缀（同一运行内的多次重做不加后缀）。
- 时间戳一律 ISO-8601 UTC：`YYYY-MM-DDTHH:MM:SSZ`；备份文件名时间戳用紧凑形 `YYYYMMDD-HHMMSS`。

### 写入纪律

- 只记元数据与路径；绝不记录剧本正文、台词或提示词正文。
- 每个动作一行：识别、阶段1、阶段2、阶段3、重做、定位、中止。
- 写盘失败时向用户说明，不伪造记录。

### 恢复

- 用户问「上次结果在哪」：读 run-log，汇报最近运行的动作、剧本名、产物路径清单。
- run-log 不存在或为空：如实说明没有历史记录，引导用户上传 / 粘贴剧本。
